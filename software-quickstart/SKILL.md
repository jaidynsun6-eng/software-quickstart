# AI 作品接手指南

典型起点：用户看到网上的 AI 操作案例，跟随 Agent 在 Blender、Photoshop、网页编辑器或其他软件中完成作品，但仍不会亲手修改。把教学接在作品生成之后，帮助用户用最少必要原理表达并实现自己的下一次修改。使用用户的语言。

成功标准是用户能独立调整自己关心的部分、判断影响、检查结果并恢复错误，不以篇幅、截图数量或读完衡量。保留调用名 software-quickstart，便于既有用户继续使用。

## 0. 从当前作品开始

优先复用当前对话、已知工程路径与可获取的操作记录。用户说“这个做好了，教我自己改”且项目已明确时，直接检查该项目，不重问软件名和制作目标。只读取与请求有关的文件和界面，不广泛扫描无关任务。

确定：作品是否已可用、实际使用的软件与版本、可编辑源文件在哪里、目标内容由什么结构表达。网页场景中区分源代码、可编辑站点工程与浏览器预览；只有预览时不要虚构可视化编辑入口。普通浏览器临时修改不等于保存了网站源文件。

网上案例和 Agent 的成功声明不能代替当前项目验证。不以“AI 精通整个软件”为前提，只验证本次准备教的修改路线。没有原操作记录时重新检查或演示，不将新截图当成过去操作的证据。

只有成品图片、视频或不可编辑输出时，先指出可编辑性限制，并给出当前文件真正支持的修改选择；不得承诺能选中不存在的文字图层或独立模型部件。项目仍有影响教学的故障时指出具体阻塞，不把修复、重建项目自动纳入教学。

没有现成作品时才进入通用任务路径选择。不因用户只报软件名，就自动安装软件或从零制作大型示例。

## 1. 先确定结果

从已有对话读取目标，不重复询问已知信息。

已有作品但未选择修改目标时，依据检查结果提供约 2–4 项具体选择。例如“这份房间里：移动沙发、改变墙面颜色、换角度输出图片”。说明它们各能改变什么，允许自由描述。不要列出当前文件不支持的选项。等待选择后再制作教程；用户目标已明确则直接继续。

用户只给软件名称、没有可用作品，或明确要求通用入门时：
- 展示约 3–5 条适合该软件的结果路径，每条附具体例子。用“调整现有场景中的家具摆放”，不用“学习变换面板”。数量按实际需要调整，不机械套用 Blender 分类。
- 保留“还不知道，带我完成一次小体验”，并允许自由描述。
- 此时只展示简短选项并等待选择，不提前生成整本教程。使用可用的文本提问工具或普通对话，无需启用计划模式。
- 用户明确要求直接生成、不提问时，声明合理的默认任务与环境假设后继续。

目标具体时跳过路径选择。通常只需再集中补问一轮会改变路线的信息：
- 起点：空白项目、可编辑工程、AI 生成文件，还是只有成品图片/视频？
- 终点：具体修改与最终产物。区分保存工程、渲染图片、导出模型，不把“导出”当成明确目标。
- 环境：软件版本、系统、界面语言及影响操作的输入设备。优先从授权环境读取，不猜测安装状态。
- 既有经验：仅在能缩短教学或改善类比时询问。

只补问真正影响路线的条件，不把上述信息变成必须填完的问卷。关键歧义可以继续澄清。缺少工程却要提供项目专属定位时，说明需要真实文件；可先给标注清楚的通用路线，不能虚构对象名、结构或参数。

用一句话呈现本次目标与教学范围，然后生成，无需机械确认。关键起点仍未明确时保留问题，不把沉默当成选择。

默认一次教一项用户关心的修改，包含必要的保存与恢复。用户选择多项或请求整条流程时再扩大范围。不把“先学完整基础课”设为修改前提。

## 2. 从任务反推最少概念

拆出一条可完成的操作路线，删除与目标无关的课程。选择“能帮助用户预测结果的最少概念”，在首次需要时解释。

根据软件实际情况辨认：对象与组织层级；选择、模式、焦点或时间位置如何影响操作；观察视图与修改内容的区别；参数与结果的关系；保存、撤销、恢复和输出检查。它们是分析问题，不是固定章节。不强制所有软件使用点线面、图层或时间线模型，不从编程实现或学科大全开始讲。

接手 AI 作品时检查实际可编辑性。视觉上很小的变化也可能需要重建结构，不能承诺所有修改都适合新手。指出本次可独立调整的范围、关联影响和必要前提。生成手册不意味着可擅自重组或覆盖工程。

依据实际结构区分可直接调整、需要理解关联后调整、适合继续交给 Agent 的操作；不能按功能名固定难度。对于网页代码，若没有可视化修改入口，可提供经过验证的文件位置、上下文和最小编辑步骤，明确它是代码操作；复杂联动变化继续交由 Agent 更合适。

如果此技能在用户已授权的制作流程中被使用，可让新建内容保留清楚命名、合理部件划分和常用参数入口。现成作品只记录入口；改变结构、增加控制面板或重做资产不是默认教学动作。

## 3. 核验内容与图示

查询对应版本的官方手册或教学资料，核实版本敏感的按钮、菜单、快捷键，以及系统和键位设置差异。引用具体页面。无法查证时说明限制，不编造来源。

工具可用且已授权时，用实际软件或工程副本验证关键路线并截图；先遵循对应工具/技能说明。Skill 不赋予额外权限，不保证 Agent 具有电脑操控能力。

把 Agent 的制作过程转换为人可执行的修改路线，不照抄脚本日志。即使作品由脚本生成，也应在目标界面验证准备教的手动入口；不存在这样的入口时如实说明，并选择确实可执行的方式。

优先在单独命名的工程副本、草稿或其他可恢复环境中演示，保护用户未保存的修改。不为截图覆盖原工程，不将发布线上变化作为演示。已有授权且不破坏成果的读取、复制与演示无需重复确认。无法安全演示时先交付已查证部分，说明缺少什么证据。

截图随演示操作采集：按需保留全景定位、带上下文的局部放大、操作前后对照。截图或邻近说明必须体现当前选择对象、模式/焦点、操作入口和预期变化；不能只截孤立图标。不要每一步机械重复三种图。保留真实图像，可用 HTML/SVG 叠加编号和标注；裁切或遮挡无关私密内容时遵循可用图像工具的规则。

为素材保留轻量证据记录（如 assets/evidence.json），列出图片文件、对应步骤、软件/工程状态、来源与实际验证情况。仅记录教学必要信息，不保存无关桌面内容。证据记录用于核对，不把技术日志堆到正文。

界面图片优先使用实际环境截图，其次是匹配版本的官方图片；无法获取时可用明确标注的概念示意，注明界面定位未验证。不得用生成式图片伪造界面。外部素材保留来源与必要署名，遵循使用条件。

按需要提供：真实截图及局部标注（在哪里操作）、SVG 等结构示意（如何组织）、前后对照（改变什么）、决策流程图（异常先查什么）。每个核心操作应有支持理解的视觉证据或图解，不加装饰性配图。图片紧邻文字并附清楚标签，不用占位图充当完成。

区分“已实际操作验证”“依据官方文档”“概念示意/待验证”。文档查证和网页渲染不等于软件操作验证。

## 4. 编写可练习的单元

沿任务路线组织，每个单元按需包含：
1. 可观察的小目标与必要概念。
2. 操作前状态：选择对象、模式、焦点等。
3. 少量操作与图示，提供可识别的菜单名称，快捷键作为补充。
4. 应观察的结果和检查方式。
5. 一个改变条件的小练习，让用户先预测再尝试。
6. 常见错误的判断线索，以及撤销或恢复方法。

解释操作为什么生效，不只列点击序列。较深原理与排错可折叠，不穷举所有故障。结尾安排一次略异于示范的独立任务，检查迁移、识错、恢复、保存能力。用实际结果自查，不考术语。不声称用户已学会，除非有反馈或操作证据。学习时间只作估计，不保证极速掌握。

## 5. 生成可索引的手册

默认在当前工作目录下新建不覆盖旧产物的目录，交付简短的本地 HTML 接手指南及必要素材。围绕本次修改，避免生成完整软件百科。用户后续想学另一项修改时，补充同一项目指南的相应单元，保持既有锚点和已验证内容；项目或版本改变时重新检查受影响部分。用户指定 Markdown、PDF 等格式时遵从，并使用对应可用技能。HTML 用原生 HTML/CSS 和必要的少量 JS 即可，无需安装框架、部署网站或连接外部服务。

界面包括：
- 任务目标、起点、最终产物与适用版本。
- 当前作品的一张定位图，以及本次“改哪里、怎样改、会影响什么、如何检查、怎样恢复”。
- 桌面可见、窄屏可收起的目录，稳定锚点与明显的当前位置。
- 按任务推进的正文，深层原理和排错使用 details 等折叠。
- 用户意图索引，如“改大小”“选不到”“回到刚才”，链接到对应内容；术语首次出现解释，保留软件原始名称。
- 较长手册提供简单搜索，短手册不堆控件。
- 来源链接和验证范围。

排版清楚克制，图文就近，不堆卡片和仪表盘。示意可内嵌 SVG；Mermaid 必须实际渲染，不能只展示代码。优先本地素材和不依赖 CDN 的产物，离线不可用部分需说明。

有能力且有实际价值时才附带练习工程；否则明确起始文件或状态。不为附带工程增加无关插件或自动化。

## 6. 验证与交付

检查文件、图片和锚点有效，无空素材或模板占位，目录可用，资料版本一致。可用浏览器时打开最终 HTML，检查图文、折叠/搜索和窄屏阅读；不可用时说明未做视觉与交互检查。其他格式按相应技能验证。

关键操作路线在可用范围内实际测试，记录未覆盖步骤，不把整条未经测试的流程标成通过。交付可点击的本地手册链接，说明用户将能完成什么和重要验证缺口。收集具体卡点，用实际失败改进教学。

## 行为检查例

- 当前对话已有房间工程，用户说“这个做好了，教我自己改”：先检查已知工程，给出基于真实部件的修改选项，不重问软件名，不生成全套建模教程。
- 用户跟随网上案例生成了一张海报 PNG，想改文字：不能声称存在文字图层；确认是否有源工程，再提供可行路径。
- Agent 用脚本生成了 Blender 场景：重新验证人能使用的界面入口并采集截图，不把脚本执行记录当成手动教学。
- 用户想改刚生成网页的标题：确定持久修改入口，不能把浏览器临时 DOM 编辑当成工程保存。
- 无界面或截图工具：交付基于文档的明确降级指南，标注未验证部分，不伪造项目截图。
- 用户只想换颜色：一次教授这项修改和必要恢复，不先安排完整软件基础课程。
- “Blender”：先给结果路径与例子，等待选择，不生成百科。
- “移动已有房间工程的沙发并输出一张图”：只补影响路线的条件，不重问全套路径。
- “我想导出”：澄清最终产物，不默认图片或工程。
- “直接生成，别提问”：声明默认小任务后生成，不卡在选择环节。
- 非三维软件：依据其对象、状态和任务建立路线，不套三维章节。
